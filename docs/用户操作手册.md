# DBA Toolkit 用户操作手册

适用范围：Windows x64 本地 Full / Update 便携包，源版本 `0.9.0`。不代表所有数据库版本和诊断场景均已真实 E2E 验证；具体证据以 Roadmap Acceptance 为准。

## 1. 首次安装

1. 从批准的发行渠道下载 Full ZIP 及 SHA256 清单。
2. 使用发行页 SHA256 核对文件；将 ZIP 解压到本机短路径，不建议网络共享或过深目录。
3. 双击 `启动.bat`，或在 PowerShell 执行：

   ```powershell
   Set-Location 'C:\DBAToolkit'
   .\启动.bat
   ```

   Full 包包含 CPython Embeddable Runtime、程序、SQL Registry、模板和四库默认 Python 驱动。目标电脑不需要安装 Python/pip，也不需要运行时互联网。
4. 校验包和内置 Registry：

   ```powershell
   .\dba.bat --version
   .\dba.bat validate
   .\dba.bat driver list
   .\dba.bat driver check
   .\dba.bat doctor
   ```

5. 编辑 `config/inventory.yaml` 或在 `config/inventory/` 放置 YAML 资产。Full 内的 Inventory 初始为空；`examples/inventory/` 是示例，不会自动连接。仅为允许的非敏感连接参数和凭据别名配置资产，不得把密码放进 YAML。
6. 让数据库管理员按 `docs/DATABASE_PERMISSIONS.md` 为监控身份准备所需只读授权。Toolkit 不执行 GRANT/REVOKE。

## 2. 日常使用

### 查看资产与验证

```powershell
.\dba.bat list
.\dba.bat validate --json
$DatabaseId = Read-Host '输入已配置的 database_id'
.\dba.bat show $DatabaseId
.\dba.bat test-connection $DatabaseId
```

诊断命令只针对指定 `database_id`，不扫描 Inventory 中的全部实例：

```powershell
.\dba.bat diagnose $DatabaseId slow
.\dba.bat diagnose $DatabaseId slow --json
.\dba.bat diagnose $DatabaseId active-sql --report '.\reports\active.html'
.\dba.bat diagnose $DatabaseId top-sql --top 20 --json
.\dba.bat diagnose $DatabaseId disk-growth
.\dba.bat diagnose $DatabaseId replication
```

Memory Grant 仅支持已有 SQL Server 范围：

```powershell
.\dba.bat diagnose $DatabaseId memory-grant --json
```

SQL Server 缓存计划使用明确会话 ID；Oracle 缓存计划要求 SQL_ID 和 CHILD_NUMBER，不自动挑选 Child：

```powershell
.\dba.bat diagnose $DatabaseId plan --session 123 --json
.\dba.bat diagnose $DatabaseId plan --sql-id '0123456789abc' --child-number 0 --json
```

诊断 `--report` 指定 HTML 文件；不指定时报告写到 `reports/`。诊断 HTML 自包含，可离线打开。`--json` 输出机器可读结果。SQL Server 计划若含 Showplan XML，还会生成 `.sqlplan`；按敏感诊断数据管理。

### 输出与数据保管

- `config/`：本机 Inventory/运行设置，不放认证秘密。
- `data/`：仅在显式选择本地加密 SQLite Credential Store 时可用；OS 凭据仍由 Windows Credential Manager 保存。不要把凭据数据库拷入发行包或仓库。
- `reports/`：HTML 报告、JSON 结果等历史输出。可能包含 SQL 和会话/对象信息，应限制访问并按组织留存规则处理。
- `logs/`：本地运行日志。不要手工把密码、Token 或连接串写入日志。
- `drivers/`：各数据库当前使用及备份的受管驱动版本。
- `driver-packages/`：本地导入的驱动 ZIP。
- `updates/`：Update ZIP、暂存包和回滚临时区。
- `backup/`：升级器保留的旧程序和驱动状态备份。

升级只替换明确列出的程序文件；配置、用户数据、报告、日志、Windows Credential Manager 和用户自选驱动在更新流程中与程序分开。

### 凭据

Inventory 仅配置已有凭据系统中的 `credential_alias`。常规数据库命令先使用现有安全 Provider；如需要 JIT，Toolkit 在隐藏输入中提示凭据，并按现有策略征求是否保存。密码不应作为命令参数传入。

凭据管理入口以 CLI 实际帮助为准：

```powershell
$CredentialAlias = Read-Host '输入 Inventory 中配置的凭据别名'
.\dba.bat credentials backend
.\dba.bat credentials list
.\dba.bat credentials show $CredentialAlias
.\dba.bat credentials test $CredentialAlias
```

SQLite 加密 Provider 是明确选择的可选方案，不会被 `auto` 自动启用。初始化或操作前阅读 `docs/CREDENTIAL_SECURITY.md`；不要仅为更新程序迁移真实凭据。旧 JSON Store 只读兼容。

如管理员已批准在本机使用 SQLite Store，可指定独立文件路径初始化并显式解锁；这会创建新凭据数据库，切勿指向未知或现存 Store：

```powershell
$StorePath = Join-Path $PWD 'data\credentials.db'
.\dba.bat credentials init --backend sqlite --store-path $StorePath
.\dba.bat credentials unlock --backend sqlite --store-path $StorePath
.\dba.bat credentials status
.\dba.bat credentials set $CredentialAlias --backend sqlite --store-path $StorePath
.\dba.bat credentials list --backend sqlite --store-path $StorePath
.\dba.bat credentials show $CredentialAlias --backend sqlite --store-path $StorePath
.\dba.bat credentials test $CredentialAlias --backend sqlite --store-path $StorePath
.\dba.bat credentials lock
```

`set` 的秘密输入由 CLI 交互提示处理；不要将密码放在命令行参数或 PowerShell 历史中。`init` 仅用于一个新 Store 路径，不能用它覆盖或迁移现有凭据 Store。

## 3. 驱动安装、兼容和回退

先检查 `docs/DRIVER_SETUP.md`。通用本地驱动包操作：

```powershell
.\dba.bat driver list
.\dba.bat driver check --database mysql
.\dba.bat driver install --file '.\driver-packages\mysql-driver.zip'
.\dba.bat driver rollback --database mysql
```

驱动 ZIP 是可执行代码，只从批准渠道获取。Toolkit 在安装时校验清单、数据库类型、Python ABI/架构、版本和包完整性；这不是发布者签名。每个数据库驱动独立管理，单库切换不应改变另外三个库。回退切换到此前的受管版本，不删除包。

- MySQL 默认 PyMySQL；PostgreSQL 默认 psycopg 3；Oracle 默认 python-oracledb Thin；SQL Server 默认 pyodbc。
- SQL Server 的 `pyodbc` 不包含 Microsoft ODBC Driver 17/18；需由系统管理员离线安装。
- Oracle Thin 不需要 Instant Client；Oracle 11g 需要 Thick/Instant Client 路径，不能仅凭驱动加载即认为已兼容。
- 实际支持版本以 driver bundle 元数据、Toolkit Version Profile 与对应验收证据为准，不要从驱动安装成功推断数据库版本已验证。

## 4. 更新和回滚

0.9.0 Full 是安装基线。正式版本从 0.10.0 起提供 Full 与自包含 Update；Update 是完整程序/runtime 载荷，可从其 manifest 接受的最低版本直接升级，不要求中间包。

1. 关闭 Toolkit。
2. 从同一发行版下载 Update ZIP 与 SHA256 清单，并核对哈希。
3. 将唯一一个 `DBAToolkit-*-Windows-x64-Update.zip` 放入安装根目录 `updates/`。
4. 双击 `升级.bat`。更新器检查正在运行的 Toolkit、包文件哈希/版本/schema/空间，并保留程序备份。默认驱动仅在证明确为随包默认驱动时才自动更新；用户自选驱动原样保留。
5. 新程序启动检查失败时更新器尝试恢复旧程序。成功后也保留备份，确认无误后再按组织政策清理。

手动回退只恢复程序与本次升级时保存的默认驱动选择，不恢复或覆盖用户数据。操作步骤见 `docs/UPDATE_GUIDE.md`。不要直接把 Update ZIP 覆盖解压到安装目录。

## 5. 只读安全边界

Toolkit 采集、校验、关联并生成报告，不代替 DBA 决策。它永远不自动执行 KILL、`pg_terminate_backend`、`pg_cancel_backend`、Oracle `ALTER SYSTEM KILL SESSION` 或其他会话处置命令。报告中的终止/取消命令仅是文本参考；必须由 DBA 在原生客户端独立核对身份后决定。

查询权限拒绝时保留数据库错误并提示检查 `docs/DATABASE_PERMISSIONS.md`。不应为使某个命令通过而给日常监控账号增加未经审核的权限。
